## Numbers

```rust
use i18n_next::{I18n, t, tn};

let i18n = I18n::builder()
    .config("i18n.json")             // numberFormats, locales[].iso
    .formats(r#"{"en": {"short": {"notation": "compact"}}}"#)
    .build()?;
i18n.tn(1234567.891);                // "1,234,567.891" in en, "1 234 567,891" in ru
i18n.tn_as(1234.5, "currency");      // a named format of the active locale: "$1,234.50"
i18n.with_locale("ar").tn(1234.5);   // ar → ar-EG by iso: "١٬٢٣٤٫٥"
i18n.text("total").number(9.99);     // {number} in a Text, as <i18n-t :number>
t!("total", @number = 9.99);         // the same with the macro
tn!(1234.5);                         // the implicit instance (scope, else global)
i18n.language_name("de");            // Some("Deutsch"): the CLDR autonym
```

`tn(value)` takes any integer or float (`impl Into<Number>`; past 2^53 an integer is the nearest
`f64`, as JS holds it) and formats it like `new Intl.NumberFormat(tag).format(value)` with the
locale's `iso` as the tag (else its code), exactly as `@i18n-micro/core` `FormatService` does:
underscores become hyphens, a tag `Intl` does not know formats as `en`. One allocation (the
result); a `Text` with `{number}` written into a buffer allocates nothing.

Named formats are Vue I18n's `numberFormats`: `{"<locale>": {"<name>": {<Intl options>}}}`, from
`i18n.json` and `Builder::formats` (a name given again wins). `tn_as` looks the name up by the
locale code, then shorter (`zh-Hant-TW` → `zh-Hant` → `zh`); a name nowhere to be found warns (debug
builds, or `tracing`) and formats with the defaults, as JS does.

Formats are computed by an own engine on CLDR 48 data, the same CLDR as Node's ICU, and checked
against `Intl` output: the shortest decimal digits of the `f64` rounded half-expand as a decimal
(`1.005` → `1.01`), the locale's pattern, grouping (`minimumGroupingDigits`, Indian `12,34,567`),
default numbering system and currency spacing. The few places where ICU formats differently from the
CLDR JSON (currency patterns of English in Europe, `fr-CH` separators, the layout of `currencyDisplay:
name`, the currency names of `sr-Cyrl-ME`) are read back from ICU when the data is generated.

| `Intl.NumberFormat` option | v1 |
| --- | --- |
| `style: decimal`, `minimumFractionDigits`, `maximumFractionDigits`, `minimumIntegerDigits` | yes |
| `useGrouping`: `true` / `false` / `"always"` / `"auto"` / `"min2"` | yes |
| `style: percent` | yes |
| `style: currency` + `currency`, `currencyDisplay: symbol / narrowSymbol / code` | yes |
| `currencyDisplay: name` | with the `currency-names` feature (the number as ICU shows it there: `€1,234.50 euros` in `en-150`, `US$1,234.50 US dollars` in `en-DE`) |
| `notation: compact` (`compactDisplay: short`), with `style: decimal` | yes |
| default numbering system of the locale (`ar-EG` → `١٬٢٣٤`); `numberingSystem` naming it | yes |
| `style: unit`, `signDisplay` other than `auto`, `roundingMode`, significant digits, `notation: scientific / engineering`, `compactDisplay: long` with compact, compact currency or percent, another `numberingSystem` | no: `Error::UnsupportedFormat` at `build()` |

Options at their default value (`notation: "standard"`, `signDisplay: "auto"`, `currencySign:
"standard"`, `numberingSystem` of the format's locale…) are accepted, unknown keys are ignored (as by
`Intl`), and values `Intl` throws on (`currency: "usdx"`, `minimumFractionDigits` over
`maximumFractionDigits`) are errors too. Values are read as `Intl` reads them: digits by `ToNumber`
(`"2"`, `"0x2"`, `null` → 0, `true` → 1, `[2]`), strings by `ToString`, `useGrouping` falsy (`0`, `""`,
`null`) is off, a key given twice takes its last value. A `-u-nu-` extension in a tag is not read.
Known differences (`fixtures/compat/README.md`): `en-US-POSIX` formats as `en-US` (ICU: no grouping),
and ICU's misplaced name where currency spacing meets a symbol of letters in `currencyDisplay: name`
(`CHF 1,234.5 Swiss francs0` in `en-DE`) is written as `CHF 1,234.50 Swiss francs`.

## Dates and relative time

```rust
i18n.td(when); i18n.td_as(when, "short"); i18n.tdr(when);
```

| `Intl.DateTimeFormat` / `RelativeTimeFormat` option | v1 |
| --- | --- |
| `dateStyle` / `timeStyle` (`short`, `medium`) | yes |
| `year`, `month`, `day`, `weekday`, `hour`, `minute`, `second`, `hour12` / `hourCycle` | yes |
| `timeZone` | yes (`tz` feature) |
| relative `numeric: always / auto`, `style: long / short / narrow` | yes |
| `timeZoneName`, `timeStyle: full / long`, `era`, other calendars | no: an error at `build()` |

An invalid date gives `"Invalid Date"`.

## Time zones and the clock

```rust
I18n::builder().time_zone("Europe/Berlin").clock(|| now).build()?;
```

The system zone is used by default (`TZ`, `/etc/localtime`, the WebView's zone in Tauri, `Intl` in the
browser). `clock` fixes "now" for `tdr` and tests.

## CLDR data and `I18N_NEXT_LOCALES`

The number data is Rust statics generated at build time (no decoder at run time; the linker drops
what an app never calls). `build.rs` takes the locales of the environment variable
`I18N_NEXT_LOCALES` with their CLDR parent chains (`de-CH` brings `de`), plus `en` (where an unknown
tag goes) and the root:

```sh
I18N_NEXT_LOCALES=en,de,ru cargo build --release   # three locales and their parents
I18N_NEXT_LOCALES=all cargo build --release        # every locale ICU has (638)
cargo build --release                              # unset or `modern`: the 425 CLDR `modern` locales
```

A tag in the list is matched like a tag at run time, aliases included (`zh-TW` is `zh-Hant`, `de-XX` is
`de`, `iw` is `he`, `sh` is `sr-Latn`); one with no data fails the build. Only the locales ICU itself has
count: a CLDR locale ICU formats as another (`az-Arab` as `az`, `be-tarask` as `be`) is left out, and a
region ICU aliases onto a script it lacks formats with the root, as in ICU (`ku-IQ`). A locale left out formats as its nearest selected parent, else `en`.
Regional variants keep only what differs from their parent, strings are interned, patterns are parsed
in `build.rs`.

`.wasm` bytes after `wasm-opt -Oz` (the size probe: catalog, `t`, `Text`, `tn` decimal, currency and
compact), measured in M5:

| `I18N_NEXT_LOCALES` | locales | full probe | data over 3 locales |
| --- | --- | --- | --- |
| `en,ru,de` | 3 (+ parents) | 197.6 KB | — |
| 10 (`en,de,fr,es,ru,ja,zh,ar,pt,hi`) | 10 | 203.1 KB | +5.5 KB |
| first 100 `modern` | 100 | 214.9 KB | +17.4 KB |
| unset (`modern`, the default) | 429 | 277.2 KB | +79.6 KB |
| `all` | 659 | 313.7 KB | +116.1 KB |

(Measured before the locales ICU resolves to another were left out: 425 and 638 now.)

`currency-names` (off by default) adds the plural display names of every currency for
`currencyDisplay: name`: about 1.7 MB of statics for the `modern` set (1 MB of text, 40 700 entries),
so pick the locales with `I18N_NEXT_LOCALES` when you turn it on.
