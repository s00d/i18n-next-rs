title: Formats
description: tn, td and tdr, named formats, time zones and the clock.
---

::note
Numbers land in M5, dates and relative time in M6.
::

```rust
i18n.tn(1234.5); i18n.tn_as(9.99, "currency");
i18n.td(when); i18n.td_as(when, "short"); i18n.tdr(when);
```

Formats are computed by an own engine on CLDR 48 data, the same CLDR as Node's ICU, and checked against
`Intl` output. Named formats come from `i18n.json` (`numberFormats`, `datetimeFormats`) and are looked up
by shortened tags (`zh-Hant-TW → zh-Hant → zh`).

| `Intl` option | v1 |
| --- | --- |
| number `decimal`, fraction / integer digits, `useGrouping` | yes |
| `percent`; `currency` with `symbol` / `narrowSymbol` / `code` / `name` | yes (`name` needs `currency-names`) |
| `notation: compact` (short) | yes |
| default numbering system (`ar-EG` → `١٬٢٣٤`) | yes |
| `dateStyle` / `timeStyle` (`short`, `medium`) | yes |
| `year`, `month`, `day`, `weekday`, `hour`, `minute`, `second`, `hour12` / `hourCycle` | yes |
| `timeZone` | yes (`tz` feature) |
| relative `numeric: always / auto`, `style: long / short / narrow` | yes |
| `style: unit`, `signDisplay`, `roundingMode`, scientific, `timeZoneName`, `timeStyle: full / long`, `era`, other calendars | no: an error at `build()` |

An unsupported option fails at `build()`, never as a silent difference from the frontend. An invalid date
gives `"Invalid Date"`.

## Time zones and the clock

```rust
I18n::builder().time_zone("Europe/Berlin").clock(|| now).build()?;
```

The system zone is used by default (`TZ`, `/etc/localtime`, the WebView's zone in Tauri, `Intl` in the
browser). `clock` fixes "now" for `tdr` and tests.
