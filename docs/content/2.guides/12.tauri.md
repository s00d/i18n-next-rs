## Transport

The frontend gets whole chunks and resolves keys itself: there is no IPC per key.

| Channel | For |
| --- | --- |
| custom protocol `i18n-next://` | data: `GET /v{version}/{locale}/{page}.json` (the chunk, raw file bytes) and `GET /v{version}/bundle?locale=…&page=…` (root of the chain + page). `ETag`, `Cache-Control: immutable` |
| IPC commands | control: `set_locale`, `get_locale`, `available_locales`, `pages`, `meta`, `report_missing` (dev) |
| raw invoke `load` / `load_page` | fallback with the same payload when the protocol is not available |
| event `i18n-next://changed { locale, version }` | a new version changes the URL, so the cache never serves old data |

Measured on macOS (WKWebView, Tauri 2.12, release, median):

| Method | 81 KB | 832 KB | 8.5 MB |
| --- | --- | --- | --- |
| custom protocol `fetch().json()` | **0.35 ms** | **2.45 ms** | **21.0 ms** |
| raw invoke + `TextDecoder` + `JSON.parse` | 0.65 | 3.05 | 24.5 |
| invoke with `serde_json::Value` | 0.65 | 4.15 | 43.0 |
| `Channel` in 256 KB chunks | 0.95 | 3.55 | 29.5 |
| `JSON.parse` of a string already in JS | 0.10 | 1.25 | 17.0 |

Moving 8.5 MB takes about 3.5 ms by any binary method; 70–85% of the time is `JSON.parse`. So the lever is
how much is sent (only the active chain, pages on demand, eviction), not how.

## Windows and locale

`set_locale` from JS or Rust switches Rust and every window; each window gets `changed` and reloads the
root and its current page. The selected locale is saved to `app_config_dir/i18n-next.json`
(`.persist(true)`, default). At start: the saved locale, else the WebView's `navigator.languages`
negotiated against your locales, else `defaultLocale`.

## Native UI

```rust
app.i18n().bind(&quit_item, app.i18n().page("tray").text("quit"));
app.i18n().bind(&window, app.i18n().text("window.title"));
```

Menu items, submenus, tray tooltip and window title are relabeled on every locale change. `unbind`
stops it. Commands that return `Text` are serialized translated.

## Missing keys in dev

In a dev build the plugin collects misses from Rust and from the frontend (`report_missing`), dedupes them
by `(locale, page, key)` and writes `app_data_dir/i18n-missing.json`. In release the command is not
registered.

## Security

Page and locale names from the frontend are accepted only if they are in the catalog; file paths are built
only from known names, so `../` or absolute paths cannot happen. The protocol handler accepts only `GET`
and checks `Origin`. Default permission: `load`, `load_page`, `get_locale`, `available_locales`, `pages`,
`set_locale`.
