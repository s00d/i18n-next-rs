`tauri-plugin-i18n-next-api` has no runtime dependency on `@i18n-micro/*`. The `/vue` entry uses the
optional peers `@i18n-micro/vue` and `vue`.

## `connect`

```ts
import { createI18n } from '@i18n-micro/runtime'
import { connect } from 'tauri-plugin-i18n-next-api'

const i18n = createI18n({ locale: 'en' })
const link = await connect(i18n, { page: 'index', maxPages: 20 })
await link.setPage('settings')   // the page's chunks, then setRoute('settings')
await link.setLocale('de')       // Rust, native labels and every window
await link.preload('about')      // loaded, not shown, never evicted, kept for every locale
await link.load('about')         // loaded for a navigation about to be confirmed; the shown page stays
link.close()                     // stop following changes (an unmounted app)
```

- **Start locale and zone.** The first call sends `navigator.languages` and the time zone (the instance's
  `timeZone`, else the WebView's); Rust picks the best available locale unless a saved one applies, and
  shows its dates in that zone unless the catalog has its own `time_zone`. The meta sends the zone back
  (`timeZone`) and `connect` formats `td` in it, so dates match Rust's.
- **Data** comes over the `i18n-next://` protocol with `fetch().json()`. URLs carry the chunk's content
  tag, so a chunk that did not change is read from the cache, also after `en → de → en`. When the protocol
  is out (the fetch fails with a network error), the raw `load` command carries the same chunks
  (`transport: 'auto'`, the default; `'protocol'` or `'invoke'` force one). An HTTP error of the protocol
  fails that call and keeps the protocol.
- **Content Security Policy.** An app with a CSP must let the WebView fetch the protocol:
  `connect-src i18n-next: http://i18n-next.localhost` (the second form is what Windows and Android use).
  Without it the fetch is blocked and `connect` falls back to raw invoke.
- **Fallback chains.** The JS core reads one locale; the catalog reads a chain (`de-at → de → en`). `connect`
  merges each view along the chain the meta lists, so `t()` answers what Rust `t` answers.
- **Changes.** Every window follows `i18n-next://changed` (a switch from the tray, another window, a reload
  in dev). An event older than what is shown is dropped.
- **Cache by version.** Going back to a page makes no call until the catalog version changes.
- `<html lang dir>` follows the locale (`document: null` turns it off).
- **`maxPages`** keeps at most that many page views; the current page and preloaded ones stay.
- **Missing keys** go to the dev report (`report_missing`, event `i18n-next://missing`), once per key,
  batched. The command exists in debug builds only: in release nothing is sent after the first refusal.

## Vue

```ts
import { createTauriI18n, useI18nLink } from 'tauri-plugin-i18n-next-api/vue'

app.use(router)
app.use(await createTauriI18n({ router }))   // any createI18n option of @i18n-micro/vue too
```

- `locale`, `locales`, `defaultLocale` and the named formats (`$tn(n, 'currency')`, `$td(d, 'short')`) come
  from Rust (`i18n.json`).
- The route already shown when `createTauriI18n` runs (a deep link) is loaded before it returns.
- `router.beforeResolve` loads the route's page before the route shows (`link.load`: the page being left
  keeps its texts), and `router.afterEach` shows it once the navigation is confirmed, in the same tick:
  no raw keys in between. A cancelled or duplicated navigation changes nothing. The page is the route name
  (`pageOf` changes that); a route without a page folder reads the root. A load error keeps what is shown
  and lets the navigation through.
- `app.unmount()` closes the link and removes the router hooks and the locale watch (`plugin.dispose()`
  does the same without an app; Vue 3.5+ for the automatic one).
- `$t`, `$tc`, `<i18n-t>`, `useI18n()` are those of `@i18n-micro/vue`, as in nuxt-i18n-micro.
- Setting the locale on the instance (`useI18n().locale.value = 'de'`) goes to Rust like
  `useI18nLink().setLocale('de')`; the old texts stay until the new ones are in. The last locale set wins;
  one Rust refuses puts the shown locale back.

## React, Preact, Solid

Their adapters build an `@i18n-micro/runtime` instance; hand it to `connect` and to the provider:

```tsx
import { createI18n, I18nProvider } from '@i18n-micro/react'   // or /preact, /solid
import { connect } from 'tauri-plugin-i18n-next-api'

const i18n = createI18n({ locale: 'en' })
const link = await connect(i18n)
root.render(<I18nProvider i18n={i18n}><App /></I18nProvider>)
// on navigation: await link.setPage(name)
```

The package tests run `connect` with all three.

## Typed keys

`@i18n-micro/types-generator` reads the same folder Rust reads and writes a declaration that types every
key of `$t`, `t()` and `<i18n-t keypath>`:

```ts
// vite.config.ts
import { I18nTypesPlugin } from '@i18n-micro/types-generator'

export default defineConfig({
  plugins: [vue(), I18nTypesPlugin({ srcDir: import.meta.dirname, translationDir: '../locales', outputFile: 'src/i18n-micro.d.ts' })],
})
```

`examples/tauri-app` uses exactly this; the generated file is rewritten on every build (keep it out of git).
