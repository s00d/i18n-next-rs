`tauri-plugin-i18n-next-api` has no runtime dependency on `@i18n-micro/*`. The `/vue` entry uses the
optional peer `@i18n-micro/vue`.

## `connect`

```ts
import { createI18n } from '@i18n-micro/runtime'
import { connect } from 'tauri-plugin-i18n-next-api'

const link = await connect(createI18n({ locale: 'en' }), { page: 'index' })
await link.setPage('settings')   // page chunks + addRouteTranslations + setRoute
await link.setLocale('de')       // Rust and every window
link.preload('about')
```

- Data comes over the custom protocol with `fetch().json()`, with `<link rel="preload">` for the root at
  start; raw invoke is the fallback.
- A `(locale, page) → version` cache: going back to a page makes no request until the version changes.
- `<html lang dir>` follows the locale.
- `maxPages` keeps at most that many page chunks; the current page and preloaded pages stay.

## Vue

```ts
import { createTauriI18n } from 'tauri-plugin-i18n-next-api/vue'
app.use(await createTauriI18n({ router }))
```

`router.beforeResolve` loads the page chunk, so a navigation finishes with its keys in place. A load error
keeps the current dictionary and does not break the navigation. `locales` and `defaultLocale` come from
the plugin's payload (`i18n.json`).

## React, Preact, Solid

Their `@i18n-micro` adapters build a runtime instance, so `connect` works with them as is. Tested in M8.

## Typed keys

Use `@i18n-micro/types-generator` as a Vite plugin pointed at your locale folder.
