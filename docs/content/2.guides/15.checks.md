## `check()`

```rust
#[test]
fn translations_are_complete() {
    let i18n = i18n_next::I18n::builder()
        .config("i18n.json")
        .dir("locales")
        .linked_messages(true)
        .build()
        .unwrap();
    let report = i18n.check();
    assert!(report.is_clean(), "{report}");
}
```

`check()` returns a `CheckReport`: `items` (sorted, one `CheckItem` per finding), `is_clean()`, and a
`Display` with one line per item:

```text
catalog check: 4 problem(s)
  - de: no file for page "about" (other locales have one)
  - de/index: "bye" is missing (the default locale has it)
  - de/index: "hi" has {nam}, the default locale {name}
  - en/index: "cars" has 2 plural forms, expected 3 (zero | one | other)
```

| Item | Reported when |
| --- | --- |
| `MissingPage` | a page has a file in some locales but not in this one (the root counts as page `index`) |
| `MissingKey` | a key of the default locale's chunk is not in the same chunk of this locale |
| `Placeholders` | the `{names}` of a key differ from the default locale's (`{count}` is not compared in plurals: `tc` fills it) |
| `PluralForms` | a message with `\|` has a form count `tc` does not read by category: expected is a zero form plus one per category the locale's small counts reach (`en`: 3, `ru`: 4); a `=0 ` message may also have one per category of the locale |
| `PluralShape` | the count fits, but the zero form has a `{` or a form shared by several counts lacks `{count}`, so `tc` reads it by index |
| `BrokenLink` | a link left a linked message as written (with `linked_messages(true)`), with the link and the reason |

- The default locale is `defaultLocale` of `i18n.json`, else the start locale (`.locale(..)`, else `en`).
- Lazy files are read for the check (a remote pair counts with what has arrived). Disabled locales are skipped. A locale whose tag has no CLDR rules (`en_US`, `xx`) uses the index rule,
  which reads any count of forms.
- Every string with a `|` is a plural for `tc`: a title like `"Home | Acme"` is reported in `en`.

## Typed keys

- Frontend: `@i18n-micro/types-generator` (see [Frontend](/guides/frontend#typed-keys)).
- Rust: not yet. Until a key generator lands, keep keys as `key!` constants in one module and let `check()`
  catch what the files lack.

## CLI

`@i18n-micro/cli` (`check`, `lint`, `translate`, export / import) works on the same files.
