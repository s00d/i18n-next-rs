The catalog is split into chunks addressed by `(locale, page)`. The root chunk has page `index`, as
`translationCacheKey` in JS.

| Chunk | File | Holds |
| --- | --- | --- |
| root | `locales/<locale>.json` | shared keys: menus, buttons, errors, tray |
| page | `locales/pages/<page>/<locale>.json` | keys of one page |

## Lookup order

The first match wins:

1. page in the active locale;
2. root in the active locale;
3. page in the fallback locale;
4. root in the fallback locale;
5. and so on down the [fallback chain](/guides/fallback).

So the root of the active locale beats the page chunk of a fallback locale, exactly as in i18n-micro.
A page chunk keeps only its own keys: the root is never copied into it, and a root edit is seen by every
page.

```rust
let settings = i18n.page("settings");          // View: Arc + name, Clone + Send + Sync
settings.t("title");                           // page → root → fallback page → fallback root
settings.t_with("hint", &Args::new().int("n", 3));
i18n.with_locale("de").page("settings").t("title");
i18n.pages();                                  // known pages: ["settings", "user-profile"]
i18n.add_messages("en", Some("settings"), r#"{"saved": "Saved"}"#)?;
```

`page("")` and `page("index")` are the root. A page with no chunk reads the root only, and a page
name is only ever a name: it is never turned into a file path.

## Rust-only pages

A page is just a name. It can match a frontend route (`settings`) or be a Rust-only area (`tray`,
`notifications`, `cli`). The frontend never loads a page it does not ask for.

```rust
let tray = i18n.page("tray");
tray.t("quit");
```

## Options

| Builder | JS equivalent | Effect |
| --- | --- | --- |
| `.pages(false)` | `disablePageLocales` | page files merge into the root; a page file wins on the same key |
| `.page_alias("about-us", "about")` | `routesLocaleLinks` | a page reads another page's chunk; an alias to nothing fails `build()` |
| `.evict_pages(n)` | — | keep at most `n` reloadable page chunks in memory (M3) |
