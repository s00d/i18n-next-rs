title: Plurals
description: Forms separated by |, index and CLDR-category rules, the =0 marker and iso tags.
---

::note
`tc!` and `.count(n)` on a `Text` pick forms the same way as `tc`.
::

```json
{
  "car": "car | cars",
  "apples": "нет яблок | {count} яблоко | {count} яблока | {count} яблок",
  "cart": "=0 Your cart is empty | {count} item | {count} items"
}
```

```rust
use i18n_next::Args;

i18n.tc("car", 2);                                   // "cars"
i18n.tc("apples", 21);                               // "21 яблоко" (ru)
i18n.tc("cart", 0);                                  // "Your cart is empty"
i18n.tc_with("greet", 3, &Args::new().str("name", "Ann"));
i18n.with_locale("ar").tc("apples", 11);             // the rules of `ar`
```

`count` is any integer, or an `f64` (feature `format`). `{count}` is filled with it, printed as JS prints
numbers; in `tc_with` it beats an argument named `count` (JS `tc(key, { ...params, count })`). An integer
past ±2^53 is what JS would hold, the nearest `f64`, for the form and for `{count}`: `u64::MAX` prints
`18446744073709552000`. `tc_with` with `Args::list` fills `{0}`, `{1}`… but not `{length}`, as a spread
array in JS.

The form is picked exactly like `pluralForm` in `@i18n-micro/core`:

- forms are split on `|` once at load and trimmed;
- by default the **index rule**: form `count`, the last form past the end (`car | cars`: 0 → `car`);
- **unmarked categories**: a zero form without `{`, then one form per CLDR category the locale's small
  counts reach (Russian: `one`, `few`, `many`), each shared form showing `{count}`. Only locales with three
  or more such categories read templates this way;
- **`=0 ` marker**: the first form for 0, the rest by category (with more forms than the small-count
  categories: every category of the locale, as `one, many, other` in French);
- a negative, fractional or `NaN` count takes the last form.

A value without `|` is its own single form; a number comes back as it is. A boolean or a subtree has no
plural: `tc` returns the default (`Args::or`, interpolated; an empty one stays empty) or the key. A miss
also calls `missing`. `t("car")` returns the whole string with its pipes, as in JS.

## The tag

Rules go by the locale's `iso` (`.iso("ua", "uk-UA")` or `"iso"` in `i18n.json`), else by its code. The tag
resolves as `Intl.PluralRules.supportedLocalesOf` does: `de-AT` → `de`, `pt-PT` keeps its own rules, `iw`
→ `he`. A tag `Intl` rejects (`en_US`) or does not know (`ua`, `xx`) gets the index rule, never the
host's locale.

One known difference: ICU stops checking a `-u-` extension after a repeated key and accepts
`ru-u-rg-rg-a1` (as `ru-u-rg`); the crate follows the BCP 47 grammar, rejects it and uses the index rule.

Rules are generated from CLDR 48 `plurals.json` by `scripts/cldr.mjs` into Rust code (40 functions, all
locales) and checked against `Intl.PluralRules` for every locale on 0..1000, decimals and large numbers.
