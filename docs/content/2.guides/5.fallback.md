---
title: Fallback and missing keys
description: Fallback chains, the missing handler and try_t.
---

```rust
let i18n = I18n::builder()
    .locale("de-at")
    .fallback("en")                 // global fallback: the weakest layer
    .fallback_for("de-at", "de")    // de-at → de → en
    .missing(|locale, key, page| eprintln!("missing {locale}/{page}/{key}"))
    .build()?;

i18n.t("nav.home");                                        // "Startseite"
i18n.t_with("cart", &Args::new().int("n", 2).or("{n} items")); // default on a miss
i18n.try_t("nav.nope");                                    // None
i18n.has("nav.home");                                      // the active locale only
i18n.locale();                                             // "de-at": Arc<str>, no allocation
```

- Each locale has a chain, as in Nuxt: `de-at → de → en`. The global fallback is always last, taken alone: its own `fallback_for` links are not followed (as `buildFallbackLocaleChain` in JS).
  `fallbackLocale` per locale in [`i18n.json`](/guides/locale-files#i18njson) adds the same steps.
  A cycle (`a → b → a`) stops at the first repeat.
- A locale needs no file of its own to be known: the start locale (`en` by default), both ends of every
  `fallback_for` link, the global fallback and `iso` codes are known too. `.fallback_for("de-ch", "de")`
  is enough to `set_locale("de-ch")`, which then reads `de`, then `en`; `locales()` lists `de-ch`.
- A miss returns the default if one is given (`Args::or`, interpolated), else the key itself, and calls
  `missing(locale, key, page)`; the root page is `"index"`.
- `try_t` and `get` return `None` instead, and never call `missing`. A subtree (`t("nav")`) returns the
  key without calling it.
- `has` checks only the active locale (its page and root), never the fallback, like JS `has()`.
- `set_locale` refuses a locale nothing defines (`Error::UnknownLocale`) or one `i18n.json` disables
  (`Error::DisabledLocale`). `with_locale` of an unknown name reads the global fallback alone, without its
  links; `with_locale` of a disabled locale reads its own chain, as a configured locale does in Nuxt.
- Every `fallback_for` target is known, so a chain never stops early on an unconfigured locale: a target
  with no messages adds no layer, which reads the same as Nuxt stopping there.

In a Tauri dev build the plugin also collects misses from the frontend; see [Tauri](/guides/tauri#missing-keys-in-dev).
