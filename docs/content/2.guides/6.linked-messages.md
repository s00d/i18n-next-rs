```json [locales/en.json]
{
  "brand": "acme",
  "title": "Welcome to @:brand",
  "shout": "@.upper:brand",
  "intro": "@.capitalize:{'nav.home'}.",
  "greet": "Hi @:withName",
  "withName": "{name}!",
  "nav": { "home": "home" }
}
```

```rust
use i18n_next::{Args, I18n};

let i18n = I18n::builder().linked_messages(true).dir("locales").build()?;
i18n.t("title");                                     // "Welcome to acme"
i18n.t("shout");                                     // "ACME"
i18n.t("intro");                                     // "Home."
i18n.t_with("greet", &Args::new().str("name", "Ann")); // "Hi Ann!"
```

The syntax and the rules are those of the Nuxt module's
[`linkedMessages: true`](https://github.com/s00d/nuxt-i18n-micro) (`@i18n-micro/utils`), checked line by
line against it (`fixtures/compat/__golden__/linked.md`, ~32k lines):

- `@:key`, `@.upper:key`, `@.lower:key`, `@.capitalize:key` (the first letter only), and `@:{'key'}` for a
  key a bare link cannot spell.
- A bare key runs to whitespace or one of `{ } @ % | ( )`, **dots and commas included**: `@:brand.` names
  `brand.` and `@:brand,` names `brand,`. End a sentence with the literal form: `@:{'brand'}.`.
- `{name}` placeholders of the linked text stay and are filled when the message is read; the modifiers
  leave them alone (`@.upper:` on `Hi {name}` gives `HI {name}`).
- A number links as JS prints it. A missing key, a subtree, a boolean, a cycle, a message that is itself
  left as written, or an unknown modifier leave the **whole** message as written. `build` calls
  `missing(locale, key, page)` once for it, and [`check()`](/guides/checks) lists each failing link with
  its reason.
- Dynamic keys (`@:{name}`) and the old `@:(key)` form are not links.
- Off by default: `@:` may already be plain text in your messages.

## Which messages a link sees

Each `(locale, page)` is resolved as a whole, over everything a lookup there reads: the page, the root, and
the same in every fallback locale, as the Nuxt module premerges a page with its fallbacks before resolving.
So:

- a page message can link a root key or a fallback locale's key;
- a root message read on a page whose file overrides the target reads the page's value;
- an English message read in German (German has no own copy) links the German words: with `"brand"`
  translated, `de.t("title")` is `"Welcome to Akme"`.

The crate keeps the layers apart instead of premerging. A result that differs from what the layer holding
the message stores is kept in the reading locale's own chunk, out of sight of `has` and `check`: they see
the locale's own keys, as without links.

## Lazy and remote files

A pair read on first use (`lazy_dir`, `lazy_files`) or brought by the app (`remote` + `add_file` /
`ensure_async`) resolves its own linked messages when it loads (again after an eviction or a `reload`),
over the other layers of its view: its page and root, then the same in each fallback locale. Lazy layers
of the view are read first, so the answer does not depend on what was read (or evicted) before. Remote
layers count once their files are in: one `ensure_async` call shows all of its files together, weakest
layer first, so the order the network answers in changes nothing. Before its files arrive a remote pair
answers its library strings and `messages`, links resolved; messages added with `add_messages` stay as
written. What is not done for such a pair:

- a message of another layer is not re-resolved for its view (an eager root message read on a lazy page
  that overrides its target keeps the root's result);
- eager messages are resolved at `build`, when no lazy file is read: a link into a lazy file stays as
  written, and `check()` says so ("names no message read at build");
- a link it leaves as written is not reported (`missing`, `check()`): a lookup has no build to report to;
- two locales that fall back to each other: a pair being loaded is not read again for the other one.

## Case rules

The modifiers use the locale's `iso` (else its code), as `toLocaleUpperCase` / `toLocaleLowerCase` do in
V8: Turkish and Azerbaijani `i` → `İ`, `I` → `ı`; Lithuanian keeps the dot above `i` under accents; Greek
upper case drops accents and breathings and keeps a dialytika where an accent was (`άυλος` → `ΑΫΛΟΣ`), a
standalone `ή` keeps its tonos. Every other tag, and a tag `Intl` rejects, gets the default Unicode
mapping. The data of these rules comes from Node's ICU (`scripts/casing.mjs`).

## Cost

Links are resolved once, in `build`: a lookup reads plain text and costs exactly what a plain message
costs (same time, same single allocation). `build` with 1000 linked messages in three locales takes about
4 ms against 0.6 ms without links.

The resolver and its case tables are linked into a binary only when it calls `linked_messages`: about
75 KB of `.wasm` (after `wasm-opt -Oz`; the Unicode case mapping is ~30 KB of it), nothing otherwise.

## Limits

- Messages added later with `add_messages` are not resolved (as `$mergeTranslations` in Nuxt), and earlier
  results stay as they were.
- Targets are read the way a lookup reads them, layer by layer: `null` never hides a weaker value. This
  differs from the Nuxt premerge only for structure conflicts between layers (`null` over a value, a scalar
  over a subtree, a flat `"a.b"` in one file beside a nested one in another).
- `@:list.length` links the length of an array in JS; a lookup has no `length`, so it is missing here.
- A locale with no files of its own reads the texts as resolved for the locale it falls back to.
