| Source | Where | What happens |
| --- | --- | --- |
| `.dir("locales")` | native, WASI | every root and page file is read at `build()` |
| `.lazy_dir("locales")` | native, WASI | `build()` only lists the `(locale, page)` pairs; a file is read by the first lookup that reaches its layer, once |
| `.files(iter)` | everywhere (Android, browser, single binary) | any iterator of `(path, bytes)`: `include_dir`, `rust-embed`; parsed at `build()` |
| `.lazy_files(iter)` | everywhere | the same, parsed on first use |
| `.messages(locale, page, json)` | everywhere | tests, generated data |
| `.remote(manifest)` | browser | the list of paths is known, the app brings the bytes (`ensure_async`, `add_file`) |
| `.extend(iter)` | everywhere | files of a library, under the app's own |

Paths use the directory layout: `de.json` is the root of `de`, `pages/settings/de.json` the
`settings` page, `pages/user/profile/de.json` the `user-profile` page.

## Lazy files

```rust
let i18n = I18n::builder().lazy_dir("locales").locale("de").fallback("en").build()?;
i18n.pages();                         // known from the file names, nothing read yet
i18n.page("settings").t("title", str::to_owned);     // reads pages/settings/de.json (and more only if needed)
```

- A lookup reads the layers it reaches: a key found on the page does not read the root.
- Each file is read once, also when many threads hit it at the same moment (the others wait
  for that one read). A lazy load changes no answer, so it sends no `Change` and keeps the
  version.
- A lazy file that cannot be read is skipped and reported (stderr in debug builds, or a
  `tracing` warning): its layer stays empty. Use `dir` / `files` if a broken file must stop
  the start.

## `remote` and `ensure_async`

```rust
const MANIFEST: [&str; 4] = ["en.json", "de.json", "pages/settings/en.json", "pages/settings/de.json"];

let i18n = I18n::builder().remote(MANIFEST).locale("de").fallback("en").build()?;
i18n.ensure_async("de", Some("settings"), |path| async move {
    let response = gloo_net::http::Request::get(&format!("/locales/{path}")).send().await?;
    response.binary().await
}).await?;
```

- `ensure_async` fetches only what the chain of the locale lacks for the page (`missing_files`
  lists it), all files at once. It needs no runtime: the closure returns any `Future`
  (gloo-net or `fetch` in the browser, `tokio::fs` in native).
- A file already being fetched by another `ensure_async` is not fetched twice: the second
  call waits for the first one's result.
- The files of one call become visible together when the last one is in (one new version,
  one `Change`), the weakest layer first, so linked messages resolve the same whatever order
  the files arrive in.
- A failed fetch leaves the catalog as it was and returns `Error::Fetch { path, message }`;
  the other files of the call are still added. Calling `ensure_async` again fetches only what
  is still missing.
- Loading by hand: `missing_files(locale, page)` gives the paths, `add_file(path, bytes)`
  adds the result. `add_file` accepts only paths of the manifest (`Error::UnknownFile`
  otherwise). A pair becomes visible when all of its files are in (one file, unless
  `pages(false)` folds page files into the root): version + 1, subscribers notified.
- Until then lookups answer from what is in: the root, the fallback, library strings and
  `messages` of that pair.

## Translations from libraries

```rust
// in the library
pub fn locales() -> impl Iterator<Item = (&'static str, &'static [u8])> { /* include_dir walk */ }

// in the app
I18n::builder().extend(my_lib::locales()).extend(other_lib::locales()).dir("locales").build()?;
```

Layers merge per `(locale, page)`, deep: `extend` calls in order, then the app's files (eager
and lazy), then `messages`. Later wins, so the app can override any string of a library.
Libraries should keep their keys under their own top-level key (`"my_lib": { … }`).

## Page eviction

```rust
I18n::builder().lazy_dir("locales").evict_pages(50).pin_page("tray").build()?;
```

At most 50 lazily loaded pages stay; loading one more drops the least recently used from the
next snapshot. Root chunks, eager chunks, pairs with `messages` / `add_messages` and pinned
pages are never evicted. An evicted local page is read again on its next use with the same
answers; a remote one is missing again until the next `ensure_async`. Eviction sends no
`Change` (no answer changed) but bumps the version so threads drop the old snapshot. The cost
on a page hit is one relaxed load of a counter (and a store at most once per load elsewhere):
the same ns as without eviction in the benches.

## Reload, subscribe and watch

```rust
let sub = i18n.subscribe(|change| println!("{} v{}", change.locale, change.version));
i18n.reload()?;     // reads every source again
drop(sub);          // unsubscribe
```

- `reload()` rebuilds from the builder's sources: `dir` files are read again, lazy pairs start
  unloaded, remote files are missing again. Readers answer from the old snapshot until the new
  one is in; a broken file makes `reload` fail and keeps the old catalog. Messages added with
  `add_messages` are not kept (pass them to the builder if they must survive).
- `subscribe` calls the listener after `set_locale` to another locale, `add_messages`,
  `reload`, an `add_file` that completes a pair and an `ensure_async` call that brought files,
  with `Change { locale, version }`. A panicking listener does not stop the others. Once its
  `Subscription` is dropped a listener is not called again (a call already running on another
  thread may finish).
- Feature `watch`: `i18n.watch()` polls the size and mtime of the `dir` / `lazy_dir` files
  every 100 ms in a thread and reloads once they stay unchanged for 150 ms (a burst of saves
  is one reload). Debug builds only; in release and on wasm it does nothing. Dropping the guard
  stops the thread.
- Feature `tracing`: misses become `warn!` events with `locale`, `page` and `key`; loads,
  `add_file` and `reload` are `debug!` events with the path, bytes and time; each
  `ensure_async` fetch runs in a `debug` span. See [Tracing](/guides/tracing).
- In a Tauri app the plugin calls `watch` for you in debug builds (`Builder::watch`).
