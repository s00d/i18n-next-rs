::note
`dir`, `files` and `messages` land in M1; `lazy_*`, `remote`, `extend`, `reload` and `watch` in M3.
::

| Source | When | Notes |
| --- | --- | --- |
| `.dir("locales")` | native, WASI | reads every root and page file at `build()` |
| `.lazy_dir(..)` / `.lazy_files(..)` | many pages | lists `(locale, page)` pairs from file names, reads a file on first use, once |
| `.files(iter)` | Android, browser, single binary | any iterator of `(path, bytes)`: `include_dir`, `rust-embed` |
| `.messages(locale, page, json)` | tests, generated data | |
| `.remote(manifest)` + `ensure_async` | browser | the app fetches the bytes |

## `remote` and `ensure_async`

```rust
let i18n = I18n::builder().remote(MANIFEST).locale("de").build()?;   // ["de.json", "pages/settings/de.json", …]
i18n.ensure_async("de", Some("settings"), |path| async move {
    gloo_net::http::Request::get(&format!("/locales/{path}")).send().await?.binary().await
}).await?;                                                          // only the files the chain still needs
```

`ensure_async` takes any closure returning a `Future`, so it works with any runtime and in native with
`tokio::fs`. `missing_files(locale, page)` and `add_file(path, bytes)` are there for loading by hand.

## Translations from libraries

```rust
I18n::builder().extend(my_lib::locales()).dir("locales").install()?;
```

Layers merge per `(locale, page)` in call order, then the app's own files: the app can override any
string of a library. Libraries should keep their keys under their own top-level key.

## Reload and watch

`reload()` rebuilds the snapshot; readers holding the old one are not affected. The `watch` feature
polls file times in debug builds and reloads changed chunks; in release it is a no-op.
