## `i18n-next`

Default: `std`, `format`, `tz`, `global`. With the defaults the crate has no runtime dependencies (CI checks it with
`cargo tree -e normal`); `tz` pulls in `js-sys` on `wasm32-unknown-unknown` only.

| Feature | Default | What it brings | Size |
| --- | --- | --- | --- |
| `format` | yes | `tn` / `td` / `tdr`, named formats, `{number}` / `{date}` / `{relativeDate}` in `Text`, `f64` counts, CLDR number and date data | the data of the locales `I18N_NEXT_LOCALES` selects, see [Browser (wasm)](/platforms/browser-wasm#size) |
| `tz` | yes | IANA time zones and the system zone (`TZ`, `/etc/localtime`, Android tzdata, `Intl` in the browser); without it dates show in UTC or a fixed offset | part of the date code (~35 KB with the date renderer) |
| `tzdb` | Windows: always with `tz` | the bundled tzdb (transitions since 1970) as a fallback after the platform's zones; Windows has no TZif files, so there `tz` includes it | 77 KB of data |
| `global` | yes | `install` and `global()`: the process-wide instance that `t!`, `Key` and the free functions fall back to; without it they read a `scope().instance(..)` or an explicit `t!(i18n => ..)` | small |
| `std` | yes | reserved; the crate needs `std` today and the feature changes nothing | none |
| `serde` | no | `Serialize` for `Text` (the displayed string), so a Tauri command or an HTTP handler can return them | `serde` |
| `payload` | no | `i18n_next::payload`: the front-end payload the Tauri plugin sends and a Rust guest applies | small |
| `tauri-guest` | no | `i18n_next::tauri_guest` on `wasm32-unknown-unknown` (a Rust front end inside Tauri, through `js-sys`); elsewhere it is only `payload` | the guest build: 186.5 KB |
| `watch` | no | `I18n::watch()`: reload `dir` / `lazy_dir` files on change, debug builds only, never on wasm | none in release |
| `tracing` | no | misses, loads and fetches as `tracing` events, see [Tracing](/guides/tracing) | `tracing` |
| `currency-names` | no | plural currency names for `currencyDisplay: "name"` | ~1.7 MB of statics for the `modern` set: pick locales |
| `chrono`, `time` | no | `Timestamp` from `chrono::DateTime<Tz>` / `NaiveDateTime` (as UTC), `time::OffsetDateTime` / `UtcDateTime` / `PrimitiveDateTime` (as UTC) | the crate you already use |

Linked messages (`Builder::linked_messages(true)`) are not a feature: the resolver and its case tables are linked in
only when the builder call is in the binary (about 75 KB of `.wasm`).

`default-features = false` is the micro build: catalog, pages, templates, plurals, `Text`, the macros with an
explicit instance and `scope`. Add `global` for `install`.

## `tauri-plugin-i18n-next`

| Feature | Default | What it brings |
| --- | --- | --- |
| `tray-icon` | no | `Relabel` for the tray icon's tooltip; turns on tauri's feature of the same name |

The plugin turns on `i18n-next`'s `payload`, `serde` and `watch`. It builds only for native targets (Tauri does not build
for wasm).

## Sizes

`.wasm` bytes after `wasm-bindgen` and `wasm-opt -Oz`, net of the std runtime, measured by `tools/size-check.sh`
(CI job `size`, `I18N_NEXT_LOCALES=en,ru,de`):

| Build | What the probe calls | Bytes | Budget |
| --- | --- | --- | --- |
| micro (`default-features = false`) | catalog from embedded files, `t`, `t_with`, a page, `tc`, `set_locale`, `Text`, `scope` | 123.2 KB | 130 KB |
| full (defaults) | the micro calls plus `tn` (decimal, currency, compact), `td` (default and a named format with its own zone), `tdr`, `{number}` / `{date}` in `Text` | 265.9 KB | 270 KB |
| guest (micro + `tauri-guest` + `global`) | `tauri_guest::connect`, `set_page`, `set_locale`, `t!` | 186.5 KB | 190 KB |

Budgets live in `tools/size-budget.env`; growth over 2% against the base commit is reported in the pull request.
