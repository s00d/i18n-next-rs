Everything is available: `dir`, `lazy_dir`, `watch`, the Tauri plugin. CI runs the test suite on Linux, macOS and
Windows with stable and Rust 1.90.

## Shipping the locales

A relative path in `dir("locales")` or `config("i18n.json")` resolves against the working directory. That is the
project under `cargo run` and `tauri dev`, but an app bundle opened from Finder, Explorer or a desktop launcher
starts somewhere else (`/` on macOS) and finds no files. Relative paths are for development only. For a release:

- **Embed** the files with `files` and `config_json`: nothing to install, the same code on every OS
  (`examples/tauri-app` does this).

  ```rust [src-tauri/src/lib.rs]
  macro_rules! file {
      ($path:literal) => { ($path, &include_bytes!(concat!("../../locales/", $path))[..]) };
  }

  let i18n = I18n::builder()
      .config_json(include_str!("../../i18n.json"))
      .files([file!("en.json"), file!("ru.json"), file!("pages/settings/en.json")])
      .build()?;
  ```

- **Ship them as resources** to keep editable files: list them in `tauri.conf.json`
  (`"bundle": { "resources": { "../locales": "locales", "../i18n.json": "i18n.json" } }`), build the catalog in
  `setup` from an absolute path and register the plugin there:

  ```rust [src-tauri/src/lib.rs]
  tauri::Builder::default()
      .setup(|app| {
          let res = app.path().resource_dir()?;
          let i18n = I18n::builder()
              .config(res.join("i18n.json"))
              .dir(res.join("locales"))
              .build()?;
          app.handle().plugin(tauri_plugin_i18n_next::Builder::new(i18n).build())?;
          Ok(())
      })
  ```

## Time zones

| Where | Named zones (`time_zone("Europe/Berlin")`, a format's `timeZone`) | The system zone |
| --- | --- | --- |
| Linux, macOS | TZif files: `$TZDIR`, `/usr/share/zoneinfo`, `/var/db/timezone/zoneinfo`, … | `TZ`, then `/etc/localtime` |
| Windows | TZif files under `$TZDIR` when set, then the bundled tzdb | `TZ`; else UTC |
| a Tauri app, any OS | as above | the WebView's zone, sent with the first `meta` |

Windows has no TZif files, so with the `tz` feature (on by default) the crate embeds a compact IANA tzdb on Windows
(77 KB, transitions since 1970, generated by `scripts/tzdb.mjs`). Elsewhere the `tzdb` feature adds the same data
as a fallback after the system's files (a container image without `/usr/share/zoneinfo`, for example).

Windows names its zones its own way ("W. Europe Standard Time"), and the crate reads no registry. A plain Rust
program on Windows shows dates in UTC unless it says otherwise:

```rust
let i18n = I18n::builder().time_zone("Europe/Berlin").build()?;   // fixed zone
// or, once and before the first date, a zone you got elsewhere (a config, the client):
let taken = i18n.set_system_time_zone("Europe/Berlin");   // false: unknown zone, or too late
```

In a Tauri app none of this is needed: the plugin passes the WebView's `Intl` zone to `set_system_time_zone`, so
Rust and the frontend format dates in the same zone on every OS.

## Release builds

- `I18N_NEXT_LOCALES` with the locales you ship: the CLDR data of the others is not built in
  ([Formats](/guides/formats#cldr-data-and-i18n_next_locales)).
- `lto = "thin"` (or `true`) and `codegen-units = 1` let the linker drop the format code an app never calls.
- `watch` and the dev missing-key report are off in release builds by themselves.
