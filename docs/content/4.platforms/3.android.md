---
title: Android
description: Embedded files instead of dir, time zone data and the system locale.
---

App resources on Android are not a regular file system, so embed the catalog with `files()` (or `lazy_files()`).
The paths keep the directory layout:

```rust [src-tauri/src/lib.rs]
macro_rules! file {
    ($path:literal) => {
        ($path, &include_bytes!(concat!("../../locales/", $path))[..])
    };
}

let i18n = I18n::builder()
    .config_json(include_str!("../../i18n.json"))
    .files([
        file!("en.json"),
        file!("ru.json"),
        file!("pages/settings/en.json"),
        file!("pages/settings/ru.json"),
    ])
    .build()?;
```

`examples/tauri-app` builds its catalog exactly this way, so the same code runs on desktop and Android
(`pnpm tauri android dev`). `include_dir` or `rust-embed` work too: any iterator of `(path, bytes)`.

- Time zones come from the system tzdata container (`/apex/com.android.tzdata/etc/tz/tzdata`, then
  `/system/usr/share/zoneinfo/tzdata`). In a Tauri app the WebView's zone is used for the system zone.
- The start locale comes from the WebView's `navigator.languages` (unless a saved one applies).
- The protocol is `http://i18n-next.localhost` on Android: allow it in the CSP
  ([Tauri](/guides/tauri#content-security-policy)). A page served from an Android dev host needs
  [`origins`](/guides/tauri#origins).
- Persist and the dev report write to the app's config and data directories (`Builder::data_dir` moves them).
