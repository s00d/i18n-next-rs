`wasm32-unknown-unknown` has nothing to read synchronously, so either embed the files with
`files()` / `lazy_files()` or load them over the network with `remote` + `ensure_async`
(`dir` and `lazy_dir` do not exist there):

```rust
use i18n_next::I18n;

const MANIFEST: [&str; 4] = ["en.json", "de.json", "pages/settings/en.json", "pages/settings/de.json"];

let i18n = I18n::builder().remote(MANIFEST).locale("de").fallback("en").build()?;

// on navigation (any async context: wasm-bindgen-futures, Leptos resources, …)
i18n.ensure_async("de", Some("settings"), |path| async move {
    let response = gloo_net::http::Request::get(&format!("/locales/{path}")).send().await?;
    response.binary().await
}).await?;
i18n.page("settings").t("title", str::to_owned);
```

- Only the files the chain still lacks are fetched, at the same time; a file another
  `ensure_async` is already fetching is fetched once.
- A failed request returns `Error::Fetch` and leaves the catalog as it was: the page answers
  from the root and the fallback until a later `ensure_async` succeeds.
- `evict_pages(n)` keeps a long-running app's memory bounded; an evicted remote page is fetched
  again by the next `ensure_async` (your router guard calls it anyway).
- The crate pulls in no `web-sys` and no HTTP client: the network is yours (gloo-net,
  `reqwest`, or the global `fetch` through `js-sys`).

The wasm tests run `ensure_async` on `wasm-bindgen-futures` with the platform's own `fetch`
of `data:` URLs in Node and headless Chrome (`wasm-bindgen-test-runner` serves no fixture
files, so the bytes travel in the URL).

- Time: `Date.now()`; local zone from `Date.getTimezoneOffset()`, named zones through `Intl`.
- `scope().wrap()` works with `wasm-bindgen-futures`.

## A full app

`examples/leptos-app` is a Leptos CSR app (`trunk serve`) on the shared `examples/locales`: `remote` +
`ensure_async` with the platform's `fetch` through `js-sys`, the start locale from `localStorage` or
`navigator.languages` (`negotiate`), `t!` / `tc!` in components, a re-render on every `Change` through
`subscribe`, `<html lang dir>` from `locales()`. The same binary runs as the frontend of a Tauri app, see
[Tauri guest](/platforms/tauri-guest).

## Size

`.wasm` bytes after `wasm-bindgen` and `wasm-opt -Oz`, net of the std runtime, as the CI `size` job measures them
(`tools/size-check.sh`, budgets in `tools/size-budget.env`; growth over 2% is reported in the pull request):

| Build | Bytes | Budget |
| --- | --- | --- |
| micro (`default-features = false`): catalog, pages, `t`, `tc`, `Text`, `scope` | 123.2 KB | 130 KB |
| full (defaults), `I18N_NEXT_LOCALES=en,ru,de`: plus `tn`, `td`, `tdr` | 265.9 KB | 270 KB |
| guest (`tauri-guest` + `global`) | 186.5 KB | 190 KB |

The full build grows with the CLDR data of the locales it carries. `I18N_NEXT_LOCALES` picks them at build time
(their CLDR parents and `en` come along):

| `I18N_NEXT_LOCALES` | Locales | Full build |
| --- | --- | --- |
| `en,ru,de` | 3 (+ parents) | 265.9 KB |
| `en,de,fr,es,ru,ja,zh,ar,pt,hi` | 10 | 306.9 KB |
| unset or `modern` (the default) | 425 | 884.3 KB |
| `all` | 638 | 1301.7 KB |

What else moves the number:

- **Dates.** An app that never formats a date links no date code or data: about 60 KB less for three locales.
- **Linked messages.** The resolver and its case tables come only with `linked_messages(true)`: about 75 KB.
- **`currency-names`.** Plural currency names for every locale built in: keep `I18N_NEXT_LOCALES` short.
- **Your profile.** `opt-level = "z"`, `lto = true`, `codegen-units = 1`, `panic = "abort"`, then
  `wasm-opt -Oz` (trunk runs it with `data-wasm-opt="z"`).

More on the data: [Formats](/guides/formats#cldr-data-and-i18n_next_locales). Benchmarks: [Performance](/performance).
