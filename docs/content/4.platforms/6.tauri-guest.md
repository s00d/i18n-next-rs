title: Tauri guest
description: A Rust frontend (Leptos, Yew, Dioxus) inside Tauri, connected to the plugin like guest-js.
---

The `tauri-guest` feature is guest-js for frontends written in Rust (`wasm32-unknown-unknown` only):

```toml [Cargo.toml]
i18n-next = { version = "0.1", features = ["tauri-guest"] }
```

```rust
use i18n_next::tauri_guest;

let i18n = tauri_guest::connect("index").await?;   // meta, the chunks of the active chain, then `changed`
i18n_next::install(i18n.clone())?;                  // t!("key") in components
let _sub = i18n.subscribe(|change| { /* render again: change.version */ });

tauri_guest::set_page("settings").await?;           // its chunks; then t!("title", @page = "settings")
tauri_guest::set_locale("de").await?;               // Rust, native labels and every window
tauri_guest::preload("about").await?;               // loaded, follows every locale
tauri_guest::load("about").await?;                  // for a navigation about to be confirmed
tauri_guest::refresh().await?;                      // read meta again (events do this by themselves)
tauri_guest::disconnect();
```

| Function | guest-js | What |
| --- | --- | --- |
| `connect(page)` | `connect(i18n, { page })` | builds an `I18n` from the plugin's `meta` and fills it; a second call while connected shows `page` on the same instance |
| `set_page(page)` | `link.setPage` | loads the page's chunks (none when current) and keeps the page following locale switches and changes |
| `set_locale(code)` | `link.setLocale` | switches Rust and every window, then loads the shown page's chain in the new locale |
| `preload(page)` | `link.preload` | loads a page without showing it; it follows every locale from then on |
| `load(page)` | `link.load` | loads a page about to be shown (a router guard) |
| `refresh()` | `link.refresh` | reads `meta` again and loads what changed |
| `disconnect()` | `link.close` | stops following events; the next `connect` reuses chunks with the same tag |

- Rust has no "shown page": a page is read with `t!(@page = ..)`, `I18n::page` or a `scope`; `set_page` loads it.
- Data comes over the same `i18n-next://` protocol (`fetch` of `convertFileSrc` URLs, cached by content tag),
  control over the plugin's commands, all through `js-sys`, without `web-sys`. When the protocol is unavailable,
  raw `load` carries the same chunks.
- The payload format lives in the crate (`payload::encode` on the plugin side, `payload::apply` here), so both
  sides share one implementation. The instance reads the whole fallback chain itself, as on the server.
- `i18n-next://changed` from Rust and other windows is followed; an older event is dropped, and a `410` (the
  catalog moved between `meta` and a read) reads `meta` again. Every call waits for the ones before it.
- Misses go to the dev report (`report_missing`) in debug builds of the app.
- Errors: `Error::Fetch` outside a Tauri WebView (no `__TAURI_INTERNALS__`) or when a command or a read fails;
  `Error::NotInstalled` for `set_page` & co. before `connect`; `Error::UnknownLocale` from `set_locale`.

## Browser and Tauri from one binary

`examples/leptos-app` runs the same Leptos code in the browser (`trunk serve`, `remote` + `ensure_async`) and as the
frontend of `examples/leptos-app/src-tauri` (`cargo tauri dev`). It checks for `__TAURI_INTERNALS__` once:

```rust
async fn show(page: &str) -> Result<(), i18n_next::Error> {
    if in_tauri() {
        return tauri_guest::set_page(page).await;
    }
    let i18n = i18n_next::global().ok_or(i18n_next::Error::NotInstalled)?;
    i18n.ensure_async(&i18n.locale(), Some(page), fetch).await
}
```

A Rust frontend under a Content Security Policy needs `'wasm-unsafe-eval'` in `script-src` besides the protocol in
`connect-src` ([Tauri](/guides/tauri#content-security-policy)). The guest build is 186.5 KB of `.wasm`
([Features](/reference/features#sizes)).
