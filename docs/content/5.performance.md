## Method

- **criterion:** a benchmark for every public function, with real sizes and worst cases. A test fails if a
  public function has no benchmark.
- **Instruction counts (gungraun):** CI counts instructions on the base commit and on the PR in one job
  and fails when the hot path grows more than 3%. The count does not depend on machine load, so it does
  not flake.
- **Allocation counts (dhat):** `Display` of `Text` without arguments — 0; `t()` — exactly 1; `get(key)` — 0.
  One extra allocation is a red test.
- **Size:** `.wasm` after `wasm-opt -Oz` and the native binary of an example; growth over 2% fails CI.

## Design rules behind the numbers

- No locks or reference-count changes on reads: a per-thread cache of the snapshot, checked with two atomic
  loads (the catalog's version, and a counter of dropped catalogs, so a cache frees the snapshot of a
  dropped catalog on its next read).
- `set_locale` shares the data and fallback chains of the previous snapshot: it only moves a pointer.
  `locale()` and `get()` hand out shared `Arc<str>`, no allocation.
- Templates are tokenized, plural rules compiled and patterns parsed at load.
- Arguments of `Text` live in an inline array of 4: building a `Text` allocates nothing.
- `#![forbid(unsafe_code)]` in both crates.

## Compared with other crates

`benches/compare` is an unpublished workspace member: rust-i18n, fluent-bundle and ICU4X are its
dev-dependencies only, never dependencies of the published crates. It runs the same workloads on each library, used the way its docs show,
and checks that all of them produce the same text before timing. What they do differently:

- **rust-i18n** compiles the locale files into the binary (`i18n!`), fills a `HashMap` from them on the first
  `t!` and returns a `Cow<str>`, borrowed on a hit without arguments. Arguments fill `%{name}` by a scan
  of the text on every call. It has no plurals and no number or date formats. Its build row is that first fill: it has
  no other load at runtime.
- **fluent-bundle** parses FTL into a resource and indexes it in a bundle per locale. A lookup is
  `get_message` + `format_pattern`, which returns a `Cow<str>`; a miss tries the next bundle, as
  `fluent-fallback` does. Bidi isolation marks are off so the text matches. Its number formatting does not
  group digits, so it is not in the number rows.
- **ICU4X** has no message catalog. It is in the plural row with the category alone (no message), and in the
  number and date rows with formatters built once. Its date input is a calendar date built outside the
  loop, while i18n-next converts a UTC timestamp through its zone on every call.
- **i18n-next** reads JSON at runtime. `t` returns a `Translation`: the stored text as a shared
  `Arc<str>`, or the key itself on a miss, with no allocation, the counterpart of the borrowed
  `Cow<str>` of rust-i18n and fluent. `get` is the same lookup as an `Option<Arc<str>>`.

## Reproduce

```bash
rm -rf target/criterion
# criterion benches only (`instructions` is gungraun, linux + valgrind)
cargo bench -p i18n-next --features payload --bench lookup --bench json --bench plural --bench linked \
  --bench sources --bench text --bench number --bench tz --bench payload --bench tauri_guest
cargo bench -p tauri-plugin-i18n-next --bench ipc
cargo bench -p compare
mkdir -p node_modules/.cache/logs
pnpm -C crates/tauri-plugin-i18n-next bench > node_modules/.cache/logs/guest-js-bench.log 2>&1
node scripts/bench-table.mjs
```
