The reference is `@i18n-micro/core` and `@i18n-micro/utils` 2.1 and `Intl` in Node 22 (ICU 78, CLDR 48).

| Area | JS | Rust |
| --- | --- | --- |
| File format and layout | `core/src/tree.ts`, `utils/load-dir.ts` | same |
| Root and page layers | `resolveLookup` | same order |
| `disablePageLocales` / `routesLocaleLinks` | options | `.pages(false)` / `.page_alias()` |
| Fallback | one `fallbackLocale` in core, chains in Nuxt | chains |
| Interpolation | `{name}`, `{0}` | same, tokenized at load |
| Plurals | `pluralForm` | literal port |
| Linked messages | `@:key`, modifiers | same, at load |
| Missing | `default \|\| key`, `missingHandler` | same, plus `try_t` |
| Formats | `Intl.*` | own engine on CLDR 48, see [Formats](/guides/formats) |
| `<i18n-t>` | `resolveText`, `foldTemplate` | `Text`, `fold`, `parts` |
| Broken file | warning, skipped | error with path |

## How it is checked

`scripts/compat.mjs` runs a case matrix through the real JS packages and `Intl` and writes golden files,
one `call → result` line per call. The Rust test runs the same calls and compares the whole file; a diff
shows exactly the lines that differ. Only JS writes these goldens. Renovate bumps `@i18n-micro/*`,
`cldr-*` and Node, and the golden diff shows what changed.

## WebView differences

The reference output is V8's `format()` (Node, WebView2, Android WebView), which turns U+202F (narrow
no-break space) in dates into a plain space. WKWebView and WebKitGTK may keep U+202F.
