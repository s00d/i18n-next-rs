The reference is `@i18n-micro/core` 2.1 and `@i18n-micro/utils` 2.1 (the versions pinned in `scripts/package.json`,
installed from npm) and `Intl` in Node 22 (ICU 78, CLDR 48).

## Parity

| Area | JS | Rust |
| --- | --- | --- |
| File format and layout | `core/src/tree.ts`, `utils/load-dir.ts` | same: dotted paths, flat keys first, arrays by index, `null` is no value, last duplicate wins |
| Root and page layers | `resolveLookup` | same order: page, root, then the same down the fallback chain |
| `disablePageLocales` / `routesLocaleLinks` | options | `.pages(false)` / `.page_alias()` |
| Fallback | one `fallbackLocale` in core, chains in the Nuxt module | chains, as `buildFallbackLocaleChain` |
| `has` | the active locale only | same |
| Interpolation | `{name}`, `{0}`, JS `\s` | same, tokenized at load |
| Plurals | `pluralForm`, `Intl.PluralRules` | literal port, CLDR 48 rules generated into Rust |
| Linked messages | `@:key`, modifiers (`linkedMessages: true`) | same, resolved at build |
| Missing | `default \|\| key`, `missingHandler` | same, plus `try_t` |
| `<i18n-t>` | `resolveText`, `foldTemplate` | `Text`, `fold`, `parts` |
| Formats | `FormatService` on `Intl.*` | own engine on CLDR 48 data, see [Formats](/guides/formats) |
| `run(locale, fn)` of `@i18n-micro/node` | per request | `scope().locale(..).run` / `.wrap` |
| Config | Nuxt module options | [`i18n.json`](/reference/i18n-json): the same fields |
| Broken file | warning, skipped | error with path (a lazy file: skipped and reported) |

`examples/nuxt-site` reads the same `examples/locales` and `examples/i18n.json` as the Rust and Tauri playgrounds;
CI generates it and compares its texts with the Rust playground's output.

## How it is checked

`scripts/compat.mjs` runs a case matrix through the real JS packages and `Intl` and writes golden files to
`fixtures/compat/__golden__/`, one `call → result` line per call. The Rust tests run the same calls, print the same
lines and compare the whole file; a diff shows exactly the lines that differ. Only JS writes these goldens, and CI
regenerates them and fails on any diff.

| Golden | What |
| --- | --- |
| `load.md`, `lookup.md`, `interpolate.md`, `options.md` | the loader, raw lookups and `has`, interpolation, page options and fallback chains |
| `plural.md`, `plural-categories.md` | `tc` and `Intl.PluralRules` for every locale on 0..1000, decimals and large numbers |
| `linked.md` | linked messages through the Nuxt module's own merge (~32 000 lines), case modifiers by tag |
| `text.md` | `resolveText` and `foldTemplate`, the props of `<i18n-t>` |
| `number*.md`, `date*.md`, `relative.md` | `Intl.NumberFormat`, `DateTimeFormat`, `RelativeTimeFormat` through `FormatService`, plus seeded random property runs |

Renovate bumps `@i18n-micro/*`, `cldr-*` and Node; the golden diff shows what changed. The format of the files:
`fixtures/compat/README.md` in the repository.

## Known differences

Each is pinned by a test and left out of the goldens on purpose.

- **Broken files.** JS warns and skips a broken or non-object file; Rust fails `build` with the path and offset.
- **Subtree as text.** `t("nav")` returns the key; JS `<i18n-t>` prints `[object Object]`.
- **Plural tags.** After a repeated `-u-` key ICU stops checking the extension and accepts `ru-u-rg-rg-a1`; Rust
  follows the BCP 47 grammar, rejects it and uses the index rule.
- **Linked messages.** `@:list.length` reads the JS `length` of an array; a lookup has no `length`. Rust reports each
  message left as written once through `missing` and lists every failing link in `check()`; JS warns once per root
  cause. Structure conflicts between layers (`null` over a value, a scalar over a subtree) are read layer by layer,
  not premerged.
- **Numbers.** `currencyDisplay: name` where ICU puts the name one character early after a letter symbol
  (`CHF 1,391,522.0 Swiss francs0` in `en-DE`): Rust writes `CHF 1,391,522.00 Swiss francs`. `en-US-POSIX` and
  `-u-va-posix` format as `en-US`. `-u-nu-` and other extensions of a tag are not read.
- **Dates.** Gregorian only: `th`, `fa`, `fa-AF`, `ps`, `shn-TH` show another calendar in ICU by default; give them
  `-u-ca-gregory` in their `iso` and both sides agree. `-u-ca-`, `-u-hc-`, `-u-nu-` of a tag are not read.
  `timeStyle: full / long`, `timeZoneName`, `era`, `dayPeriod`, `fractionalSecondDigits` fail `build` with
  `Error::UnsupportedFormat`.
- **Unsupported number options.** `style: unit`, `signDisplay` other than `auto`, `roundingMode`, significant digits,
  scientific and engineering notation, long compact: `Error::UnsupportedFormat` at `build`, never a silent
  difference.
- **Named zones** come from the OS (or the bundled tzdb); a tzdb older or newer than Node's may differ for recent
  rule changes.

## WebView differences

The reference output is V8's `format()` (Node, WebView2, Android WebView), which turns U+202F (narrow no-break space)
in dates into a plain space; Rust does the same. WKWebView and WebKitGTK may keep U+202F, so a date formatted by the
WebView and one formatted by Rust can differ in that one character there. The ICU version of each WebView decides
its CLDR data: Rust's is CLDR 48 everywhere.
