Tests check scenarios through the public entry point, not single functions: the crate through `I18n` and
the macros, the plugin through IPC, guest-js through its exported API.

## Layout

```
crates/i18n-next/                 the crate
crates/tauri-plugin-i18n-next/    the plugin, guest-js/ and its tests
scripts/                          generators: compat goldens, CLDR data, tzdb, bench table
docs/                             this site (own pnpm project)
examples/                         playgrounds on one shared locales/ folder
```

## Commands

```bash
cargo nextest run --workspace
pnpm install
pnpm typecheck && pnpm test && pnpm build   # guest-js, incl. publint and attw
pnpm docs:generate                           # this site
```

Write full logs to a file (`target/logs/<task>.log`, `node_modules/.cache/logs/<task>.log`) instead of
cutting them with `tail`.

## Kinds of tests

| Kind | What | Where |
| --- | --- | --- |
| Models | proptest runs random sequences of user actions with a fixed seed and checks each answer against a small reference model, then session invariants | `catalog_model.rs`, `loading_model.rs`, `text_model.rs`, `scope_model.rs`, `ipc_model.rs`, `connect.model.test.ts` |
| Stories | Given / When / Then for one stream of events: timing, races, order | `stories.rs` |
| Compat goldens | `call → result` lines written by the real JS library | `fixtures/compat/__golden__/` |
| Own goldens | e.g. the payload schema; update with `UPDATE_GOLDEN=1` and read the whole diff | `tests/__golden__/` |
| Differential | own JSON reader, hasher and `tz` against `serde_json`, JSONTestSuite and `jiff` (dev-dependencies only) | |
| wasm | the same goldens and stories in Node and headless Chrome via `wasm-bindgen-test`; `wasm32-wasip1` with wasmtime | `tests/wasm/` |

`tests/support/` simulates the environment: locale trees, a virtual clock, `FakeFetch`, a manual executor
and a guard that fails a test on any unexpected miss or warning.

## Rules

- No real time in tests: virtual clocks and events, no `sleep`.
- No retries. A test that fails once in a hundred runs is a bug, in the code or in the test.
- `cargo nextest` profiles: `default` with a hard timeout per test, `ci` with JUnit, `mutants` with a
  short timeout.
- Every public function has a benchmark; hot-path functions also have an allocation check.
- No new runtime dependency in `i18n-next` without the owner's decision and a measurement.

## Mutation testing

Run locally, per crate:

```bash
export TMPDIR="$PWD/target/mutants-tmp" && mkdir -p "$TMPDIR"
cargo mutants -p i18n-next
git diff origin/main.. > target/pr.diff && cargo mutants -p i18n-next --in-diff target/pr.diff
```

A surviving mutant means the scenarios miss something: extend a model or a story. Exclusions are allowed
only for code that does not build on the host, equivalent mutants, and `Debug` / log text, each with a
reason.
