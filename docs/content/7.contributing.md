Tests check scenarios through the public entry point, not single functions: the crate through `I18n` and the
macros, the plugin through IPC, guest-js through its exported API.

## Layout

```
crates/i18n-next/                 the crate
crates/tauri-plugin-i18n-next/    the plugin, guest-js/ and its tests
scripts/                          generators: compat goldens, CLDR data, case tables, tzdb
tools/                            the size probe and tools/size-check.sh
api/                              public API snapshots (cargo public-api)
fixtures/compat/                  goldens written by the JS library
examples/                         playgrounds on one shared locales/ folder
benches/compare/                  benchmarks against other i18n crates
docs/                             this site (own pnpm project)
```

## Gate

What CI runs, in the order worth running it locally. Write full logs to a file (`target/logs/<task>.log`,
`node_modules/.cache/logs/<task>.log`) and read them whole instead of cutting them with `tail`.

```bash
# Rust
cargo fmt --all --check
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo nextest run --workspace --locked
cargo nextest run -p i18n-next --locked --features payload        # also: serde, currency-names
cargo nextest run -p i18n-next --locked --no-default-features      # the micro build
cargo test --doc --workspace --locked

# wasm
cargo build -p i18n-next --locked --target wasm32-unknown-unknown --features tauri-guest
cargo test -p i18n-next --locked --target wasm32-unknown-unknown --features tauri-guest   # Node; CHROMEDRIVER=… for Chrome
cargo test -p i18n-next --locked --target wasm32-wasip1                                   # wasmtime
tools/size-check.sh                                                # .wasm budgets

# guest-js
pnpm install
pnpm typecheck && pnpm test && pnpm build                          # incl. publint and attw

# playgrounds and docs
cargo run -p playground-rust --locked -- --check                   # the tour over every locale, fails on a miss
pnpm -C docs generate && node docs/scripts/check-links.mjs         # this site, zero broken links
```

Also in CI: `cargo deny`, `cargo machete`, the dependency check (no runtime dependency of `i18n-next` with default
features), instruction counts (`perf`), the public API snapshot and the playground builds.

## Goldens

| Goldens | Written by | Regenerate |
| --- | --- | --- |
| `fixtures/compat/__golden__/` (lookup, plurals, linked, text, formats) | the real JS library and `Intl` in Node 22 | `pnpm -C scripts install && pnpm -C scripts compat` |
| plural rules, CLDR format data, `plural-categories.md`, `number-locales*.md` | `scripts/cldr.mjs` | `pnpm -C scripts cldr` |
| case tables of linked messages | `scripts/casing.mjs` | `pnpm -C scripts casing` |
| the bundled tzdb | `scripts/tzdb.mjs` | `node scripts/tzdb.mjs` |
| payload schema, guest-js random cases (`crates/tauri-plugin-i18n-next/tests/`) | the Rust tests | `UPDATE_GOLDEN=1 cargo nextest run -p tauri-plugin-i18n-next` |
| `api/*.txt` | `cargo public-api` (nightly) | the commands in the `public-api` job of `.github/workflows/ci.yml` |

Rust never rewrites a compat golden: a Rust test that disagrees with one is a Rust bug (or a known difference, listed
in `fixtures/compat/README.md` with its reason). CI regenerates the generated files and fails on any diff. After
`UPDATE_GOLDEN=1`, read the whole diff before committing it.

## Kinds of tests

| Kind | What | Where |
| --- | --- | --- |
| Models | proptest runs random sequences of user actions with a fixed seed and checks each answer against a small reference model, then session invariants | `catalog_model.rs`, `loading_model.rs`, `text_model.rs`, `scope_model.rs`, `linked_model.rs`, `ipc_model.rs`, `connect.model.test.ts` |
| Stories | Given / When / Then for one stream of events: timing, races, order | `stories.rs`, `date_stories.rs`, `source_stories.rs` |
| Compat goldens | `call → result` lines written by the real JS library | `fixtures/compat/__golden__/` |
| Own goldens | the payload schema, guest-js cases | `crates/tauri-plugin-i18n-next/tests/__golden__/` |
| Differential | own JSON reader and `tz` against `serde_json`, JSONTestSuite and `jiff` (dev-dependencies only) | `json_differential.rs`, `tz_differential.rs` |
| Allocations | dhat counts: `get` 0, `t` exactly 1, `Display` of a `Text` without arguments 0 | `alloc.rs`, `json_alloc.rs`, `linked_alloc.rs` |
| wasm | the same goldens and stories in Node and headless Chrome via `wasm-bindgen-test`; `wasm32-wasip1` with wasmtime | `wasm.rs`, `tauri_guest.rs`, `wasi.rs` |

`tests/support/` simulates the environment: locale trees, a virtual clock, a fake fetch, a manual executor and a
guard that fails a test on any unexpected miss or warning.

## Rules

- **No flaky tests.** A test that fails once in a hundred runs is a bug, in the code or in the test: find the root
  cause and fix it. No retries, no "rerun until green", no larger timeout to hide it.
- **No real time.** Virtual clocks and events, never `sleep` or a wall-clock limit in a test.
- `cargo nextest` profiles: `default` with a hard timeout per test, `ci` with JUnit, `mutants` with a short timeout.
- Every public function has a benchmark (a test fails otherwise); hot-path functions also have an allocation check.
- No new runtime dependency in `i18n-next` without the owner's decision and a measurement.
- A change of `api/*.txt` is a public API change: it shows up in the diff and goes through the semver check.

## Mutation testing

Run locally, per crate:

```bash
export TMPDIR="$PWD/target/mutants-tmp" && mkdir -p "$TMPDIR"
cargo mutants -p i18n-next -j 4
git diff origin/main.. > target/pr.diff && cargo mutants -p i18n-next --in-diff target/pr.diff
```

A surviving mutant means the scenarios miss something: extend a model or a story. Exclusions (`.cargo/mutants.toml`)
are allowed only for code that does not build on the host, equivalent mutants, and `Debug` / log text, each with a
reason.

## Benchmarks

```bash
cargo bench -p i18n-next                    # criterion
cargo bench -p i18n-next --bench instructions   # instruction counts (gungraun, needs valgrind)
```

## Docs

This site lives in `docs/` (Nuxt 4, `@nuxt/content`). `docs/scripts/generate.mjs` writes the JS API, types,
commands and permissions pages from the sources, and the changelog; edit the sources, not those pages.
`pnpm -C docs generate` builds the static site into `docs/.output/public`, and `node docs/scripts/check-links.mjs`
checks every internal link and anchor in it.
